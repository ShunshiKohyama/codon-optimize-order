# codon-order

タンパク質配列をコドン最適化し、**合成業者が実際に作れるかどうかでゲートをかける**ツールです。

「業者サイトで最適化して、複雑度スコアの色を見て、引っかかったものを手で作り直す」という
手作業のループを、再現可能な1コマンドに置き換えます。タンパク質と両端の配列の表を渡すと、
発注できる断片、貼り付けるだけの発注シート、そしてそれを生み出した全パラメータの記録が返ります。

*[English → README.md](README.md)*

```bash
codon-order --input fragments.csv --out-prefix batch1
```

```
2 fragments; default host=e_coli; gate=complexity < 7.0
sfGFP_untagged  (238 aa, host=e_coli)
    stage 1: 2571 valid heads -> dG_open 3.1 kcal/mol, rank 1 feasible (20 codons frozen)
    sfGFP_untagged: 717 bp  CAI=0.9043  dG_open5'=3.1  complexity=4.0  pad=0  flags=''
...
wrote batch1.csv
wrote batch1.order.csv   <- 業者のバルク入力欄に貼り付ける
wrote batch1.meta.json
```

## インストール

```bash
conda env create -f environment.yml && conda activate codon-order
# 既存の環境に入れる場合:
pip install -e .
```

Python 3.11 以上が必要です。ViennaRNA は 5' 構造の段に必須で、無い場合はその段が
スキップされて実行は完走します。

## 入力

**1行1断片**です。タグ付きとタグ無し、あるいは2プラスミド系の両側のように
**両端配列が違う構築を1回の実行に混ぜられ**、発注シートも1枚で済みます。

| 列 | 必須 | 意味 |
|---|---|---|
| `name` | ✔ | 断片名。業者の `Name` 列になります |
| `protein` | ✔ | 逆翻訳するアミノ酸配列 |
| `adapter5` | | 5' 側に**逐語で**付加。最適化の対象外 |
| `adapter3` | | 3' 側に**逐語で**付加。最適化の対象外 |
| `stop` | | ORF に付ける停止コドン。**両端配列が供給する場合は空**にします |
| `utr5` | | 組み立て後の実 5'UTR。折り畳み計算にのみ使用 |
| `species` | | 行ごとのコドン表。バッチが単一宿主でない場合 |

省略した列はコマンドラインの同名フラグにフォールバックするので、均一なバッチなら
`name` と `protein` だけで足ります。`examples/fragments.csv` を参照してください。

## 何をしているか

**1. ローカルで最適化** — [DnaChisel](https://github.com/Edinburgh-Genome-Foundry/DnaChisel)
で CAI を最大化し、反復 k-mer とヘアピンを最小化し、合成または発現を壊すパターンを禁止します
（ホモポリマー、ポリメラーゼ停止部位、細菌宿主なら内部 Shine-Dalgarno・強い RBS・
Chi site・潜在的開始コドン）。

**2. 開始点を先に決めて、残りを最適化する。** stage 1 が最初の20コドンの同義コドンを探索して
**最も構造を作らない 5' 末端**を選び、そこを凍結します。stage 2 はその下流だけを最適化します。
**コドン選択が CAI 経由で発現を動かす量はわずかですが、5' mRNA 構造経由で動かす量は大きく**、
パイプライン中でそこに介入できるのはこの段だけです。

**3. 製造可能性でゲートをかける。** まず安価なローカル指標で候補を評価し、それを通ったものだけ
業者に実スコアを問い合わせます。閾値以上なら反復ペナルティを上げて再最適化します。
**合成可能性を実際に買うのは反復の抑制**です。

各設定の根拠と、**採用しなかった案とその理由**は [`docs/design.md`](docs/design.md) にあります。
**パラメータを変える前に読んでください。**

## 再現性

DnaChisel の探索は確率的です。`--seed`（既定 `0`）でバッチは**バイト単位で再現**します。
`<prefix>.meta.json` に全パラメータ・入力パス・バージョン・ゲートの結果が記録されるので、
数ヶ月後でも**発注したのと同一の断片を再生成**できます。

## 複雑度ゲート

任意です。認証情報が無くても最適化は完走し、業者の列が空になるだけです。
その場合は業者サイトでスコアを確認してから発注してください。使う場合は:

```bash
cp .env.example .env     # 中身を記入。.env は git-ignored です
codon-order-complexity --check-auth
```

現在は IDT の SciTools Plus API（eBlock 複雑度スクリーニング）に対応しています。

## 落とし穴

実際に時間を溶かしたものを挙げます。**いずれもツール側では検出できません。**

### 両端配列が開始コドンを供給している場合

融合タンパクの上流側が `…ATG` で終わっている場合、**その ATG がそのタンパク質の開始 Met です**。
`adapter5` に含めて、**`protein` は2残基目から**書いてください。さもないと Met が二重になります。
開始コドンは最適化できないので、これによる損失はありません。明示するだけの問題です。

**発注前に、組み立てた断片を翻訳して設計を確認してください。** ツールの出力は配列1列だけで、
残基の重複には気づきません。

### `stop` とパディングは相互作用する

`--min-length` に足りない断片を伸ばすパディングは **ORF と 3' 側配列の間**に入ります。
これが正しいのは **ORF が自前の停止コドンを持っているとき**だけです。`stop` が空のとき
（両端配列が停止コドンを供給する、あるいは C 末端融合が続く）、同じ詰め物は**翻訳されます**。
そのためツールはこの場合**パディングを拒否して停止**し、3' 側配列を自分で伸ばすよう促します。
逐語の両端配列の**どこに停止コドンがあるかをツールは知り得ない**ためです。

### `--n-candidates 1` は 5' 側の段を切らない

これは stage 2 が**候補から選び直すのを止める**だけです。stage 1 は依然として探索して
head を凍結します。5' 側の機構を完全に切るには **`--head-samples 0`** を使ってください。

### 断片が翻訳開始点でないなら stage 1 を切る

融合タンパクの内部断片（N 末端タグより下流のすべて）には、**それ自身の翻訳開始が存在しません**。
最初の20コドンを構造のために凍結しても、**リボソームが載らない領域を守っている**だけです。
コストは小さい（CAI の数パーセント）ものの、利益はゼロです。真核生物宿主も同じで、
翻訳開始はキャップ依存スキャンなので**細菌の結果は転用できません**。`--head-samples 0` を使います。

### `dg_open_5p` は校正されていない

**絶対値は無意味**とみなし、**バッチ内での順位**（`dg_open_pct`、100 が最も構造的）だけを
判断材料にしてください。値は折り畳み窓・UTR・ViennaRNA のパラメータセットで動きます。
**床もあります** — 概ね 2 kcal/mol を下回ると候補間の差は意味を持ちません。

### `utr5` が無いと 5' の数値は暫定値

決定的な窓は開始コドンをまたぐので、ORF 単独の折り畳みは妥当な近似ですが、
**UTR との接合部にできる構造は見えません**。組み立て後の転写開始点が分かるなら渡してください。

### 業者の認証は 401 ではなく 500 を返す

IDT のトークン endpoint は **password grant の失敗**に
`500 {"Message":"An error has occurred."}` を返します。パスワード間違いでも
存在しないユーザーでも**同じ応答**です。client が不正な場合は
`400 {"error":"invalid_client"}` になるので、切り分けはこうなります。

- `invalid_client` → `IDT_CLIENT_ID` / `IDT_CLIENT_SECRET` が違う
- **`500` → client は正しく、拒否されているのは「アカウントのログイン」**

**再試行で調べようとしないでください。** API はこれ以上何も返さず、
**失敗の繰り返しでアカウントがロックされる**恐れがあります。ユーザー名とパスワードは
**ウェブサイトに手でログインして検証**し、アカウント名とメールアドレスの
**両方を試してください**（どちらが要求されるかは実測しかありません）。

### 他の宿主には `--species` だけでは足りない

`--species` は CAI のコドン表を差し替えます（`python_codon_tables` 同梱は
`e_coli` / `b_subtilis` / `s_cerevisiae` / `h_sapiens` / `m_musculus` /
`d_melanogaster` / `c_elegans` / `g_gallus`）。一方で**宿主依存の制約はもっと粗い分類**に従います。

| 宿主 | 適用される制約 |
|---|---|
| `e_coli` | 全部：汎用 + 内部 SD / 強い RBS + Chi site + 潜在的開始コドン |
| その他の登録済み細菌 | 汎用 + 内部 SD / 強い RBS |
| それ以外 | 汎用パターンのみ |

**真核生物ではこれだけでは不十分です。** Kozak 文脈、CpG、スプライス部位の扱いが別途必要で、
`--head-samples 0` も渡すべきです。登録外の細菌を扱う場合は
`src/codon_order/optimize.py` の `BACTERIAL_SPECIES` に追加してください。

しかも最良の窓は **Shine-Dalgarno 配列と重なっていません**。
